# NVMe-enabled U-Boot for CM4/RPi4

This folder contains tooling for building a Raspberry Pi 64-bit `uboot-mender`
binary set with NVMe support enabled.

## What it changes

The patch file `patches/uboot-mender-rpi64-nvme.patch` changes:

- `rpi_arm64_defconfig`:
  - enables `CONFIG_NVME`
  - enables `CONFIG_NVME_PCI`
  - enables `CONFIG_CMD_NVME`
  - keeps preboot unchanged (`pci enum; usb start;`)
- `include/config_mender_defines.h`:
  - switches Mender storage interface to `nvme`
  - switches rootfs base path to `/dev/nvme0n1p`
  - sets Mender pre-setup commands to `pci enum; sleep 1; nvme scan;`
- `include/env_mender.h`:
  - avoids unconditional `mmc dev ...` in RPi bootcmd path
- `drivers/nvme/*.c`:
  - enables memory decode + bus mastering for NVMe PCI device
  - adds conservative controller settle delay in PCI probe
  - translates all NVMe DMA/PRP/queue addresses with DM DMA offset
    (`dev_phys_to_bus`), so non-identity `dma-ranges` works on CM4
- `drivers/core/of_addr.c`:
  - fixes `dma-ranges` cell parsing (`of_get_dma_range`) for nested bus nodes
- `drivers/pci/pcie_brcmstb.c`:
  - increases post-PERST link wait and adds extra settle delay after link-up
  - adds fallback inbound DMA window when `dma-ranges` is missing/invalid
  - prints resolved inbound DMA window for runtime diagnostics

## Build

Run from repository root:

```bash
scripts/uboot/build-uboot-rpi64-nvme.sh
```

Output tarball is written to `assets/` by default:

`assets/raspberrypi_arm64_cm4_nvme-2024.04.tar.gz`

The tarball includes:

- `u-boot.bin`
- `fw_printenv`
- `fw_env.config`
- `uboot-git-log.txt`

## Use with mender-convert

Use:

- `configs/local/cm4_nvme_trixie_64_ab6gb_config`

`mender-convert` first checks `assets/` for the configured tarball name, so no
additional URL hosting is required for local builds.

## Important note about U-Boot environment storage

Default `fw_env.config` generated by this script points to `/dev/mmcblk0` raw
offsets (`0x400000`, `0x800000`). If your hardware has no MMC/eMMC backend for
the U-Boot environment, adjust your U-Boot environment backend accordingly.

If a previous U-Boot environment already exists in those offsets, old `mender_*`
variables (for example `mmc` defaults) can override the new NVMe defaults.
After flashing a new U-Boot build, reset env once from the U-Boot console:

```bash
env default -a
saveenv
reset
```
